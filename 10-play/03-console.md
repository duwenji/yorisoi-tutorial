# 10-3 Play Console の申告

[目次](../README.md) ＞ 第 10 部 ＞ 10-3

## この章で学ぶこと

- Play Console に何を申告するのか（アプリのコンテンツ・ストアの掲載情報）
- データ セーフティ: アプリが送る情報を、コードから読み取って答える
- フォアグラウンドサービスの申告: マニフェストの 1 行が、申告と動画につながる
- プライバシーポリシーを、コードと同じリポジトリで管理する理由
- 送る情報を変えたときの順番

## 申告は、コードの説明書

Play Console には、アプリについての **申告** を入れます。散策ガイドの答えは、すべて [play-console.md](https://github.com/duwenji/yorisoi-sanpoguide/blob/main/docs/play-console.md) に書いてあり、Play Console の答えはそこを元にします。

| 場所 | 入れるもの |
|---|---|
| [ポリシーとプログラム] > [アプリのコンテンツ] | データ セーフティ・アプリのアクセス権・広告・コンテンツのレーティング・対象年齢・フォアグラウンドサービスなど |
| [ユーザーを増やす] > [ストアの掲載情報] | アプリ名・説明文・アイコン・スクリーンショットなど |

申告は、アプリが **実際にしていること** の説明です。だから、答えはコードから決まります。コードを変えたのに申告を直さなければ、申告が嘘になり、審査で止められたり、ストアから外されたりします。申告を Play Console の画面だけに置かず、コードと同じリポジトリの文書にしているのは、PR でコードと一緒に直せるようにするためです。

## データ セーフティ

**データ セーフティ** は、アプリがどんな情報を集め、どう扱うかを、ストアの散策者に見せる欄です。

### 「収集」の意味に注意

Google の定義では、**端末の外に送るものは、送り先が運営者のサーバーでなくても「収集」** です（端末の中だけで処理するものと、エンドツーエンドで暗号化するものだけが例外。HTTPS は当たりません）。

散策ガイドは運営のサーバーに位置を送りませんが、スポットを探すために Overpass に、天気を調べるために Open-Meteo に、位置を送ります（[4-1](../04-outside/01-http-json.md)）。だから「位置を収集する」と答えます。「うちのサーバーには何も残さないから、収集していない」は、Google の定義では間違いです。

### コードから答えを読む

[play-console.md の「収集するデータ」](https://github.com/duwenji/yorisoi-sanpoguide/blob/main/docs/play-console.md#収集するデータ)の表は、コードのどこで何を送っているかから作っています。

| データの種類 | 収集 | 共有 | 一時的な処理 | どのコードか |
|---|---|---|---|---|
| おおよその位置・正確な位置 | はい | いいえ | はい | スポット・ルート・天気の検索（kit-geo、[4-1](../04-outside/01-http-json.md)） |
| その他のユーザー作成コンテンツ（散策の状況のまとめ） | はい | いいえ | はい | AI へのプロンプト（[4-3](../04-outside/03-ai.md)） |
| デバイスまたはその他の ID | はい | いいえ | いいえ | 運営の AI の中継へのインストール ID（[4-3](../04-outside/03-ai.md)、[8-9](../08-aws/09-ai-relay.md)） |

- **共有はいいえ**: 外のサービスに送るのは、散策者が求めた機能のためで、相手に別の目的で使わせるために渡すのではないから
- **一時的な処理**: 位置と散策の状況は、運営も保管しない（中継は内容を保存しない、[8-9](../08-aws/09-ai-relay.md) の「残さないもの」）。インストール ID は、中継が HMAC にして 7 日保管するので「いいえ」
- **申告しないもの**: 散歩の記録・設定・API キーは端末の外に出ない。バックアップと端末間の移行からも外している（[4-5](../04-outside/05-storage.md)、`data_extraction_rules.xml`）

[8-9](../08-aws/09-ai-relay.md) で「中継はプロンプトを保存しない」とテストで守っていたのは、この申告を本当にしておくためでもあります。

答えは、Play Console の画面の「CSV にエクスポート」と同じ形の CSV（[play-data-safety.csv](https://github.com/duwenji/yorisoi-sanpoguide/blob/main/docs/play-data-safety.csv)）にもしてあり、[10-4](04-api.md) の道具で API から入れられます。

## フォアグラウンドサービスの申告

[3-2](../03-walk/02-service.md) で、散策中は `WalkService` がフォアグラウンドサービスとして位置を追うのを見ました。マニフェストには、こう書いてあります。

```xml
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_LOCATION" />
<!-- … -->
<service
    android:name=".walk.WalkService"
    android:exported="false"
    android:foregroundServiceType="location" />
```

`foregroundServiceType="location"` の 1 行が、Play Console の **フォアグラウンドサービスの申告** を求めます。位置を追い続けるのは散策者の電池とプライバシーに関わるので、Google は「なぜ要るのか」を説明させ、**実際に使っている様子の動画** まで求めます。

| 項目 | 散策ガイドの答え |
|---|---|
| 種類 | 位置情報 |
| バックグラウンドの位置の権限 | 求めない（`ACCESS_BACKGROUND_LOCATION` なし。散策者が「散策をはじめる」を押してから始める） |
| 説明 | 「散策をはじめる」から「散策を終える」まで、画面を閉じても現在地を追い、近づいたスポットの解説と距離・経路の記録をする |
| 動画 | 「散策をはじめる」→ 通知が出る → 画面を閉じる → スポットに近づくと案内が出る → 「散策を終える」 |

`ACCESS_BACKGROUND_LOCATION` を求めないのは、設計の選択です。「散策者が自分で始めた散策の間だけ、通知を出して追う」なら、フォアグラウンドサービスの位置で足ります。常に位置を取れるバックグラウンドの権限は、審査も散策者の目も厳しくなります。

申告の動画は、リポジトリの `store/videos/` に置き、CDN（jsDelivr）の **コミットを固定した URL** を Play Console に入れています。`@main` のように枝の名前で指すと、CDN に古い版が残ることがあるからです（[play-console.md の「フォアグラウンドサービスの申告」](https://github.com/duwenji/yorisoi-sanpoguide/blob/main/docs/play-console.md#フォアグラウンドサービスの申告)）。

## プライバシーポリシー

位置の権限を使うアプリには、プライバシーポリシーの URL が要ります。散策ガイドは、[privacy-policy.md](https://github.com/duwenji/yorisoi-sanpoguide/blob/main/docs/privacy-policy.md) を GitHub Pages（リポジトリの `docs/` を Web に出す GitHub の機能）で公開しています。出すページの選び方と、URL を変えてはいけない理由は [11-6](../11-github/06-pages-releases.md) で見ます。

ポリシーもコードと同じリポジトリにあるので、送る情報を変える PR で、ポリシーも一緒に直せます。

## ストアの掲載情報

アプリ名（30 文字）・簡単な説明（80 文字）・詳しい説明（4,000 文字）・アイコン・フィーチャー グラフィック・スクリーンショットを入れます。散策ガイドは、説明文も [play-console.md の「ストアの掲載情報」](https://github.com/duwenji/yorisoi-sanpoguide/blob/main/docs/play-console.md#ストアの掲載情報)のコードブロックに置き、[10-4](04-api.md) の道具がそこから読んで送ります。

決まりの例:

- 「AI」「無料」のような宣伝の言葉をアプリ名に足さない（キーワードの詰め込みになる）
- 星・絵文字・「No.1」などの誇張を使わない
- 運営の AI に 1 日の回数の上限があること、自分の API キーではその利用料が散策者に請求されることを、必ず書く
- 位置を外に送ることは、データ セーフティの答えと食い違わないように書く
- スクリーンショットに、API キーや自宅の周りの位置を写さない

生成 AI の文章を表示するアプリなので、コンテンツのレーティングの質問票では、生成 AI の利用を「はい」と答えます。

## 送る情報を変えたときの順番

アプリが送る情報を変えるとき（たとえば運営の AI の中継を足したとき）は、次の順に進めます（[play-console.md の「送る情報を変えたとき」](https://github.com/duwenji/yorisoi-sanpoguide/blob/main/docs/play-console.md#送る情報を変えたとき)）。

1. プライバシーポリシーを直して公開する。**アプリの更新より先に**
2. データ セーフティ（とストアの説明文）を直す
3. 新しい版と **同じ審査** に出す

別々に出すと、「アプリはもう送っているのに、申告はまだ」という期間ができます。その間に申告と動きが食い違っていると、審査で止められる理由になります。

## ハンズオン: コードから申告を確かめる

AWS も Play Console も要りません。コードを読んで、申告と食い違っていないかを確かめます。

### 1. 外に送っている先を数える

```sh
cd ../yorisoi-platform
grep -rhoE 'https://[a-z0-9.-]+' kit-geo/src/main kit-llm/src/main | sort -u
```

Overpass（スポット）・ルート・Open-Meteo（天気）・Wikimedia（写真）・地図のタイル・AI のサービスの宛先が並びます（API キーを作るページの URL も混じります）。地図のタイルも、どの辺りを見ているかが相手に分かります。どれも、位置か散策の状況が伝わりうる先です。データ セーフティの「収集」を「いいえ」にできない理由が、ここから分かります。

### 2. バックアップの外し方を確かめる

```sh
cd ../yorisoi-sanpoguide
grep -n "allowBackup\|dataExtractionRules" app/src/main/AndroidManifest.xml
cat app/src/main/res/xml/data_extraction_rules.xml
```

Android 11 以前は `allowBackup="false"`、12 以降は `data_extraction_rules.xml` で、クラウドのバックアップと端末間の移行のどちらからも、すべてを外しています。「散歩の記録と API キーは端末の外に出ない」という申告が、ここで本当になっています。

### 3. フォアグラウンドサービスの種類を確かめる

```sh
grep -n "FOREGROUND_SERVICE\|foregroundServiceType\|BACKGROUND_LOCATION" app/src/main/AndroidManifest.xml
```

`FOREGROUND_SERVICE_LOCATION` と `foregroundServiceType="location"` があり、`ACCESS_BACKGROUND_LOCATION` はありません。申告の「バックグラウンドの位置の権限: 求めない」と合っています。

## つまずきやすいところ

- **外に送れば「収集」**: 運営のサーバーに残さなくても、外のサービスに送るなら申告する
- **申告とコードを同じ PR で直す**: 文書をリポジトリに置いておけば、レビューで食い違いに気づける
- **プライバシーポリシーはアプリより先に**: 送り始める前に、説明を公開しておく
- **バックグラウンドの位置の権限は、本当に要るときだけ**: 散策者が始めた間だけならフォアグラウンドサービスで足りる
- **動画やポリシーの URL は、変わらない場所を指す**: コミットを固定する

## 確認問題

<summary>問 1. 散策ガイドは、運営のサーバーに位置を保存しません。それでもデータ セーフティで「位置を収集する」と答えるのはなぜですか。</summary>

Google の定義では、端末の外に送るものは、送り先が運営のサーバーでなくても「収集」になるからです。散策ガイドは、スポットや天気を調べるために、Overpass や Open-Meteo に位置を送っています。

</details>

<details>
<summary>問 2. 運営の AI の中継を足すとき、プライバシーポリシーの更新をアプリの更新より先に公開するのはなぜですか。</summary>

アプリが中継に情報を送り始める前に、そのことを説明しておくためです。順番が逆だと、送っているのに説明がない期間ができます。データ セーフティも新しい版と同じ審査に出し、申告とアプリの動きが食い違う期間を作らないようにします。

</details>
